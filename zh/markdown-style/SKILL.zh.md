# Markdown 文档风格指南

专业的 Markdown 格式化助手。将任意内容重新格式化为结构清晰、排版专业、风格统一的 markdown 文档。支持中文、英文及中英混合文档。

## 何时使用此 Skill

当用户需要编写或编辑 markdown 文档时，始终使用此 skill：

- 撰写新的 markdown 文档
- 编辑或修改已有的 markdown 内容
- 格式化、润色或优化 markdown 文档
- 将文档重组为标准化结构
- 修复标题层级、间距或代码块格式不一致的问题
- 修复中文或中英混合文本中的 CJK 空格与标点问题
- 统一混用的术语或不一致的风格

## 工作流程

### 步骤 1：理解内容

先通读全文，识别核心主题、逻辑结构和关键数据。确定文档的主要语言——中文、英文或混合语言。在完全理解作者意图之前，不要开始格式化。

### 步骤 2：应用标题层级

**对于中文或中英混合文档**，使用中文数字编号体系：

```
# 文档标题
## 一、章节标题
### 1.1 子章节
#### 1.1.1 细节标题
```

- 二级标题（`##`）：使用中文序数词（一、二、三、四……）
- 三级标题（`###`）：使用阿拉伯数字编号（1.1, 1.2, 2.1……）
- 四级标题（`####`）：使用阿拉伯数字编号（1.1.1, 1.1.2……）
- 编号部分与标题文字之间有且仅有一个空格
- 最终章节固定为 `## 总结`（若原文包含前瞻性内容，可调整为 `## 总结与展望`）

**对于纯英文文档**，使用英文常规标题：

```
# Document Title
## Section Title
### Subsection
#### Detail
```

- 英文标题不使用数字前缀
- 使用描述性、简洁的章节标题，统一采用标题大小写或句子大小写

### 步骤 3：格式化代码与技术术语

- 所有技术术语、命令、参数、文件名、包名、变量名统一用反引号包裹（`` `code` ``）
- 围栏代码块**必须**指定语言标识符；无法判断时默认使用 `plaintext`
- 原文中的代码、命令、API 名称、数值、日期**一字不差**保留

### 步骤 4：修复空格与标点

**对于中英混合内容**：

| 规则 | 示例 |
|------|------|
| 中文 + 英文之间：加半角空格 | `使用 Python 进行数据分析` |
| 中文 + 数字之间：加半角空格 | `共有 128 个样本` |
| 英文/数字 + 中文标点：不加空格 | `MacBook Air。`, `2024 年。` |
| 中文内容：使用全角标点 | `， 。 ！ ？ ： ；` |
| 英文整句：使用半角标点 | 标准 ASCII |
| 中文并列：使用 `、` | `苹果、橙子、香蕉` |
| 英文并列：使用 `,` | `apples, oranges, bananas` |

**对于纯英文内容**：使用标准英文排版规则，不适用 CJK 空格规则。

### 步骤 5：应用间距与结构规则

- 每个标题**前后各空一行**
- 段落之间**空一行**
- 每个围栏代码块**前后各空一行**
- 分隔线 `---` **前后各空一行**
- 简单列表项之间不空行（除非某项包含多个独立段落）
- 无序列表：始终使用 `-`（连字符 + 一个空格）
- 有序列表：使用 `1.`（自动递增）
- 嵌套列表：续行缩进 2 个空格，保持对齐

### 步骤 6：润色语言质量

**对于中文内容**：

- 消除歧义：确保代词（其、该、此、这）指代明确，必要时重复关键名词
- 拆分长句：每个分句长度不超过 30 字，技术描述可放宽至 40 字
- 统一术语：同一概念全文使用相同术语，禁止混用同义词
- 主动优先：被动语态使用率控制在 20% 以下；如将"文件被删除"改为"删除了文件"
- 肯定表达：多用肯定句，少用双重否定
- 语气中立：保持专业客观，杜绝口语化、网络热词或情绪化表达
- 严格区分"的、地、得"：
  - 形容词 + **的** + 名词（`清晰的思路`）
  - 副词 + **地** + 动词（`快速地响应`）
  - 动词 + **得** + 补语（`执行得很顺利`）
- 英文复数名词翻译为中文时还原为单数（`files` → `文件`，而非 `文件们`）
- 每段 3～5 句，以中心句开头
- 并列列表项保持语法结构平行（同为名词短语或同为动宾短语）

**对于英文内容**：

- 使用清晰简洁的句子
- 优先使用主动语态；避免双重否定
- 保持术语一致性
- 保持专业中立的语气

### 步骤 7：输出格式化文档

仅输出完整的、格式化后的 markdown 文档。在标题后添加 `> 摘要：` 引用块，用 2～3 句话概括核心观点。不包含目录。

## 快速参考

### 文本样式

| 用途 | 语法 | 使用场景 |
|------|------|----------|
| 加粗 | `**文本**` | 关键点、术语首次定义 |
| 斜体 | `*文本*` | 书名、引用、轻微强调 |
| 粗斜体 | `***文本***` | 强烈强调（慎用） |
| 删除线 | `~~文本~~` | 废弃或不推荐的内容 |
| 高亮 | `==文本==` | 突出显示（仅当渲染环境支持时使用） |
| 行内代码 | `` `code` `` | 所有技术元素 |

### 列表格式

| 规则 | 细节 |
|------|------|
| 无序列表标记 | `-` + 一个空格 |
| 有序列表标记 | `1.` + 一个空格 |
| 续行缩进 | 2 个空格 |
| 列表项间空行 | 仅当某项包含多个段落时 |

### 表格

```markdown
| 名称 | 类型 | 说明 |
|:-----|:----:|-----:|
| 左对齐 | 居中 | 右对齐 |
```

### 引用与脚注

```markdown
> 注意：用于提示、警告或直接引用。

正文包含脚注[^1]。

[^1]: 脚注说明文字。
```

## 禁止事项

**严格禁止**以下行为：

- 添加原文没有的新观点、数据、案例或示例
- 修改或删除代码、命令、API、数值、日期
- 使用 Emoji 表情符号（😊、✅、🔥 等）——须删除输入中的所有 emoji
- 改变作者的核心结论或立场
- 将非表格内容强行转为表格
- 在同一文档中混合使用不同的标题编号体系
- 重写、扩写或改变作者的原始意图
- 对不足 100 字的内容进行强行扩充——应先向用户请求更多材料

## 不确定时

| 情况 | 处理方式 |
|------|----------|
| 输入为纯英文 | 翻译为简体中文，专有名词（人名、产品名、书名）保留英文原名 |
| 输入包含 emoji | 全部删除，根据上下文替换为标点或保留纯文字 |
| 代码块未指定语言 | 默认使用 `plaintext` |
| 脚注编号冲突 | 保留原有编号，新增脚注从最大编号 +1 开始 |
| 内容严重碎片化 | 先按逻辑重组段落，再执行格式化；若无法重组，在输出开头加注 `⚠️ 原文结构较散，已尽力整理` |
| 信息逻辑矛盾 | 先输出 `⚠️ 原文存疑：[具体问题描述]`，再继续整理 |
| 中英混合输入 | 不翻译，保留原文语言，应用 CJK 空格 + 中文格式化规则 |
