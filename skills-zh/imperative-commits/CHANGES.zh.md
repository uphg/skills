## 2026-08-24 — 恢复强制语义

维护者反馈：本技能的目的是统一强制祈使句规范，而非向仓库既有规范妥协。回退了当天早些时候加入的冲突裁决行为，同时保留结构性改进。

### 变更清单

### 1. `SKILL.md` → 修订

- description 恢复 "Enforces/强制" 表述，并注明规则对所有提交统一执行、不依赖仓库历史；删除从其约定条款。
- 移除工作流程第 1 步（先检查仓库既有规范并从其约定）；规则无条件适用于每条提交标题。
- 「与约定式提交的区别」改写：本技能明确选择祈使句风格（写 `Add login`，不写 `feat: add login`）。
- 禁止事项反转：绝不书写或接受非祈使句标题，即使是为了迎合周边历史。
- 「无法确定时」修改：默认套用三条规则；仅当用户对某条提交明确提出其他风格要求时才可偏离。

### 2. `SKILL.zh.md` → 同步

中文版同步以上修改，结构与英文版一致。

### 3. `evals.json` → 重写

用例 1 不再期待仓库规范检查；用例 2 改为期待约定式风格标题被标记而非接受；用例 3 从「遵从 CONTRIBUTING.md」反转为「无视约定式历史仍强制祈使句」。

### 4. `README.md` / `README.zh.md` → 更新

描述行重新同步（移除从其约定表述）。

## 2026-08-24 — 审查修订

按 skill-dev 审查清单完成修订：调整为标准格式结构、补充规范冲突裁决规则，并新增评估用例。

### 变更清单

### 1. `SKILL.md` → 修订

- 重写 description：去掉言过其实的 "Enforces"；补充触发场景（执行提交、审查/修正提交信息、检验提交质量、答疑），并注明仓库既有规范优先。
- 按仓库技能格式新增「适用场景」「工作流程」（检查既有规范 → 应用规则 → 检验并修正）「禁止事项」「无法确定时」章节。
- 合并重复的规则（"祈使语气" 与 "动词原形"）：四条规则 → 三条。
- 补充理由：Git 自身生成的消息就是祈使句（`Merge branch …`、`Revert …`）。
- 明确适用范围：仅限标题行；首字母大写仅适用于拉丁字母书写的标题。
- 移除与四条规则重复的「快速检查清单」，改为第 3 步的检验并修正流程。
- 新增裁决规则：先查看 `git log` / `CONTRIBUTING.md`，若仓库已采用约定式提交等更严格规范则从其约定，绝不标记或改写合法历史。

### 2. `SKILL.zh.md` → 同步

### 3. `evals.json` → 新建
